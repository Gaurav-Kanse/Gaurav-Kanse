### The short version

Most people specialize in one layer of the stack. I move across all of them — training a model, wiring the backend that serves it, shipping the interface around it, and occasionally building the 3D world it lives in.

I'm a CS student, and I'd rather understand a system down to its syscalls than trust it as a black box.

Currently deepening: **Deep Learning, NLP, Django, Rust, System Design.**

<br>

### What I actually build

| Layer | Stack |
|---|---|
| **AI/ML** | ML & deep learning models, NLP, AI-powered apps, inference systems |
| **Full-Stack** | React, Python, FastAPI, Django, REST APIs, auth, databases |
| **Systems** | Linux internals, process management, Unix sockets, systemd, CLI automation |
| **3D / Interactive** | 3D scene composition, interactive environments, visual storytelling |

<br>

### How it connects

```
   AI/ML  ──▶  Backend  ──▶  Frontend
 (models,     (APIs, DB,      (the part
   data)       services)     people touch)

        Linux/Systems runs underneath all of it
        3D/Interactive is where I go to build worlds, not just apps
```

<br>

### Why I build this way

A model is only as good as the system serving it. A backend is only as good as the interface exposing it. I build up and down that chain on purpose — it's the only way to actually own what you ship.
